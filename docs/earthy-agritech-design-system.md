# "Earthy Agritech" design system

Generated by Google Stitch (prompted 2026-09-29) and applied to the live app as the shared
CSS tokens in `app/web/src/index.css`, so every screen picks it up automatically — no
page-by-page rewrite. The Stitch export (9 mockup screens + this spec) is kept for reference
in the project owner's Downloads as `stitch_organic_carbon_farming_portal.zip`; it is not
checked into the repo because the mockups invent features the app doesn't have (carbon
credits, wholesale pricing, a voice assistant) — only the *visual language* below was adopted.

## Why only the tokens, not the mockup markup

The app already used this same green palette (the code's own comment called it "the palette
used across the Organic Carbon Farming documentation diagrams"), so Stitch's output is
genuinely the same design system, refined — not a different one. Reskinning through the
shared tokens and base element rules (`:root`, `h1`/`h2`, `button`, `input`, `.card`, …)
applies it everywhere at once, with no risk to the working checkout/payment/stock logic on a
site with real sales. Rewriting every page to match the mockups' exact markup (and their
invented content) would be a much larger, riskier change for no visual benefit the token
approach doesn't already deliver.

## What changed

- **Type pairing:** headings (`h1`, `h2`, the brand wordmark) now set `--font-heading`
  ("Plus Jakarta Sans"); body text and controls stay on `--font-body` ("Inter"). Both are
  loaded from Google Fonts in `app/web/index.html`, alongside Noto Sans Telugu so the Telugu
  line of every bilingual label renders in a matching weight instead of the OS's default
  Telugu font.
- **Neutrals warmed up:** ink, soft-ink, faint-ink, card and border tokens were retuned to
  the spec's parchment/earth values (`--ink: #16261E`, `--card-border: #E4E7D9`, …) — less
  green-grey, more warm earth.
- **New accent tokens:** `--warning` / `--warning-soft` (terracotta, `#C95A2B`) for
  pending/attention states, and `--info` / `--info-soft` (muted slate, `#3A6966`) for
  informational states. Defined for future use; nothing was recoloured to use them yet —
  see "Left for later" below.
- **Shadows:** warm-tinted (soil/moss `rgba(22,38,30,…)`) instead of neutral grey, per the
  spec's elevation system.
- **Shape scale:** `--radius-sm` (8px, small thumbnails/badges), `--radius-control` (12px,
  buttons/inputs/cards-that-act-like-rows), `--radius-card` (16px, `.card`/`.feature-card`,
  the primary container shape) — replacing a flatter 8/12px-only scale.
- **Inputs:** background moved from the page's parchment tone to white (`--card`), taller
  padding, a focus ring with the spec's soft ambient glow.

## Deliberately left unchanged

- **No fixed desktop width cap.** The spec's 1280px-centred desktop grid was not applied —
  this app made an explicit, prior product decision to stay fluid at every width ("no page is
  capped to a fixed width... every screen uses the whole window"). That decision stands.
- **Bilingual weighting.** The spec asks for the Telugu sub-label to sit at 80% opacity,
  visually subordinate to the English line, everywhere. This app's existing rule is the
  opposite, and deliberate: "neither line is visually subordinate to the other" (see the
  `.bi-en`/`.bi-te` comment in `index.css`). The handful of places that already de-emphasised
  Telugu (headings, buttons) were left as they were; it was not extended further.
- **Status-colour semantics** (order status, payment status, stock-movement type, membership
  label, …) still use the single existing `--accent` / `--danger` pairing everywhere, not the
  spec's four-way Paid/Info/Pending/Expired mapping. Re-mapping ~15 different status
  enumerations across the app to the new `--warning`/`--info` tokens is a real design pass in
  its own right (auditing what each status value means, not just a token swap) — left for a
  dedicated follow-up rather than folded into this change.
- **Button/input minimum heights.** The spec asks for 52px on mobile; several dense admin
  screens (data tables, the stock-adjustment panel, the taxonomy tree editor) rely on
  tighter, already-tested row actions. Left at the existing 48px rather than risk their
  layouts for a few extra px of tap target.
