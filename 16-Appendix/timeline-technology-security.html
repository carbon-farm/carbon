Technology

Recommended stack

Chosen to satisfy the Charter's own guiding principles — Cloud Native, Modular, API First, DDD, and Future AI Ready — without over-building for traffic Phase 1 doesn't have yet.

Stack by layer
LayerRecommendationWhy
BackendNestJS (Node.js/TypeScript)Modular, DI-based structure maps directly onto Modular Architecture + DDD; native CQRS and event-driven support.
DatabasePostgreSQL, primary OLTPRelational integrity for Case/Farm-Land/Order data; JSONB for flexible fields; mature and cloud-portable.
ORMPrismaType-safe schema, strong migration story for a fast-moving Phase 1 schema.
Dashboard read modelMaterialized views / read-replica on domain eventsImplements the CQRS note already in the Charter (Module 2) — avoids the dashboard fanning out live under low-bandwidth conditions.
SearchPostgres full-text + Module 14 taxonomy filtersMatches the Charter's non-AI, index/category-based search constraint exactly; vector search stays a Phase 2 concern.
Cache / queueRedis + BullMQNotifications, media processing, publication events, SLA-breach checks.
Object storageS3-compatible (AWS S3 / Cloudflare R2 / MinIO)Backs the centralized Media Library with signed URLs, never public buckets.
Farmer appPWA first, Capacitor-wrapped native laterMatches low-bandwidth/low-literacy constraints; one codebase, installable, offline draft caching.
Admin / Expert / ModeratorReact + TypeScript SPADesktop/tablet-first, matching those personas.
NotificationsWhatsApp Business API, SMS, FCM, transactional emailCovers all five channels in Module 12.
PaymentsRazorpay / UPI-native gateway, hosted checkoutKeeps card data out of platform-owned systems entirely.
DevOpsDocker + GitHub Actions, managed cloud or VPSCloud Native without over-committing to Kubernetes early.
Observabilitypino logging, Sentry, uptime monitoringNeeded for the SLA-breach visibility Mission Principle MP2 depends on.
Security

Security approach

Covers authentication and access control, data protection under India's DPDP Act 2023, payment scope reduction, and the audit trail the Charter already treats as binding.

Controls by area
AreaApproach
AuthNMobile number + password, SMS OTP for verification/recovery; JWT access token + refresh rotation.
AuthZRBAC across Farmer, Expert, Moderator, Administrator, Vendor, Support — enforced at the API layer. Expert Portal access gated behind Module 10 credential verification before a token is issued.
Data at rest / in transitEncryption at rest for database and object storage; TLS 1.2+ everywhere; no plaintext PII in logs.
DPDP Act 2023Explicit consent at registration; data minimization; anonymize — never hard-delete — a farmer's identity in Closed cases/articles on an erasure request, preserving Audit Trail and Knowledge Repository integrity.
Payment securityPCI scope kept minimal via hosted checkout/tokenization — the platform never stores card data.
API securityRate limiting, strict input validation, OWASP Top 10 mitigations, WAF in front of the API gateway.
Audit trailAppend-only, tamper-evident log of every case transition, content publication, order transaction, and expert/moderator assignment.
Media/content securityFile-type validation and malware scanning on every Media Library upload; access via short-lived signed URLs, never public buckets.
Secrets managementManaged secrets store (AWS Secrets Manager / Doppler / Vault) — never in source control or plain env files.
Mobile/PWAEncrypted local storage for client-persisted Draft cases — not plaintext.
Incident responseWritten breach-notification procedure aligned with DPDP Act timelines, owned by the Security & Compliance function.
